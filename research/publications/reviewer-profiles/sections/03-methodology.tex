\section{Methodology}

\subsection{Profile Architecture}

\subsubsection{Profile Format Specification}

Each reviewer profile is a structured markdown file with YAML frontmatter conforming to the following schema (JSON Schema provided in Appendix A):

\begin{itemize}
\item \textbf{Metadata} (required): Name, affiliation, category, keywords
\item \textbf{Research Background} (required): 2-3 sentence expertise overview
\item \textbf{Key Publications} (required): 3-5 representative papers with citations
\item \textbf{Evaluation Lens} (required): Characteristic questions the reviewer asks
\item \textbf{Review Criteria} (required): Structured checklist aligned with research priorities
\item \textbf{Voice \& Tone} (required): Style guide for generating reviews in this persona
\item \textbf{Version} (required): Profile version for tracking updates
\end{itemize}

Profiles average 2KB each (min: 1.5KB, max: 3KB, σ = 0.4KB), stored in \texttt{context/panel/reviewers/profiles/\{name\}.md}. The structured format enables validation, composition, and future optimization (Section~\ref{sec:future-work}).

\subsubsection{Profile Generation Protocol}

Profiles are generated from the 11.5KB reviewer database using the following algorithm:

\begin{enumerate}
\item \textbf{Input}: Database entry for reviewer (YAML format, avg 250 bytes)
\item \textbf{Extraction}: Retain core fields (name, affiliation, expertise, key question)
\item \textbf{Augmentation}: Add research background from publications (3-5 papers via citation search)
\item \textbf{Expansion}: Generate evaluation lens from expertise keywords and representative work
\item \textbf{Voice synthesis}: Analyze writing samples (if available) or infer from domain conventions
\item \textbf{Validation}: Verify against schema, ensure required fields populated
\item \textbf{Output}: Markdown file (~2KB) with YAML frontmatter
\end{enumerate}

Reference implementation provided in supplementary materials. Example transformations for three reviewers (Percy Liang, Michael Bernstein, Ben Shneiderman) included in Appendix B.

\subsection{Resolution Chain}

The profile loader implements a three-tier fallback with session-level caching:

\begin{enumerate}
\item \textbf{Exact match}: \texttt{profiles/percy-liang.md}
\item \textbf{Slug match}: Convert "Percy Liang" $\rightarrow$ \texttt{percy-liang.md}
\item \textbf{Database fallback}: Extract from \texttt{REVIEWER-DATABASE.md} (current behavior)
\end{enumerate}

Session-level caching (rather than global) ensures profile updates propagate within bounded time while avoiding invalidation complexity. Cache scope: one paper review cycle (5 reviewers × 2 rounds). Alternative caching strategies discussed in Section~\ref{sec:discussion-caching}.

\subsection{Experimental Design}

\subsubsection{Sample Size \& Power Analysis}

We conduct experiments with \textbf{n=25 papers} across 10 venues to achieve 80\% statistical power for detecting a medium effect size (Cohen's d = 0.5) at α = 0.05. Venues selected to span diverse review cultures:

\begin{itemize}
\item \textbf{HCI}: CHI (3 papers), CSCW (2 papers)
\item \textbf{ML}: NeurIPS (3 papers), ICML (3 papers), AAAI (2 papers)
\item \textbf{NLP}: ACL (3 papers), EMNLP (2 papers)
\item \textbf{Systems}: PLDI (2 papers), OSDI (2 papers)
\item \textbf{Theory}: STOC (2 papers), WWW (1 paper)
\end{itemize}

Sample size calculated using paired t-test assumptions: µ\_diff = 15\% token reduction, σ\_diff = 20\% (conservative estimate from pilot), power = 0.80, α = 0.05 (two-tailed). Pilot data (n=5) used only for effect size estimation, not included in final analysis.

\subsubsection{Three-Condition Ablation Study}

To isolate the source of efficiency gains, each paper undergoes three conditions:

\begin{itemize}
\item \textbf{Condition A (Fresh)}: Database regenerated per review (baseline, no caching)
\item \textbf{Condition B (Cached-DB)}: Database loaded once and cached (tests caching benefit)
\item \textbf{Condition C (Profiles)}: Persistent profiles loaded once (tests profile design benefit)
\end{itemize}

This design isolates two mechanisms: (1) caching benefit (B vs A) and (2) profile compression benefit (C vs B). If B ≈ C, gains come primarily from caching; if C >> B, profile architecture provides additional value beyond caching alone.

\subsubsection{Measurement Instrumentation}

Token measurement protocol (reproducible via logging harness in supplementary materials):

\begin{itemize}
\item \textbf{Counting method}: Anthropic API response field \texttt{usage.input\_tokens} (includes system prompt, excludes output tokens)
\item \textbf{Granularity}: Per-reviewer, per-round, per-paper (aggregated post-hoc)
\item \textbf{Scope}: Reviewer context tokens only (persona injection), excluding paper content and instructions
\item \textbf{Logging}: JSON-formatted log entries with timestamp, paper ID, reviewer ID, condition, token count
\item \textbf{Validation}: Cross-check 10\% of logs with tiktoken library (GPT-4 tokenizer) for consistency
\end{itemize}

Example log entry:
\begin{verbatim}
{"ts": "2026-03-15T10:23:41Z", "paper": "p07", "reviewer": "percy-liang",
 "condition": "profiles", "input_tokens": 487, "reviewer_context": 234}
\end{verbatim}

\subsection{Metrics}

\subsubsection{Token Efficiency}

Reduction percentage calculated as: $\frac{\text{tokens}_{baseline} - \text{tokens}_{profiles}}{\text{tokens}_{baseline}} \times 100\%$. Reported with 95\% confidence intervals via bootstrap resampling (1000 iterations). Per-venue breakdown provided to identify variance sources.

\subsubsection{Quality Preservation}

Decomposed into three subscores (each 1-5 scale):

\begin{itemize}
\item \textbf{Domain Accuracy}: Citations precise, technical details correct
\item \textbf{Citation Precision}: References relevant publications accurately
\item \textbf{Argumentation Depth}: Reasoning thorough, not superficial
\end{itemize}

Aggregate quality score = mean of subscores. Validation via human evaluation: 3 expert judges (blinded) rate 30 review pairs (baseline vs profiles) on each dimension. Inter-rater agreement measured via Cohen's κ. Hypothesis: subscores indistinguishable between conditions (paired t-test, α = 0.05).

\subsubsection{Consistency}

Cross-round correlation: semantic similarity of Round 1 vs Round 2 reviews from same reviewer (BERT embeddings, cosine distance). Higher consistency indicates stable persona across invocations. Reported per-reviewer with aggregate statistics (µ, σ, range).

\subsubsection{Diversity}

Inter-reviewer perspective variation measured via:
\begin{itemize}
\item Vocabulary overlap (Jaccard similarity of technical terms)
\item Critique focus distribution (entropy over identified issue categories)
\item Score variance (std dev of ratings across reviewers)
\end{itemize}

Negative controls: (1) all reviewers use identical profile (diversity floor), (2) fully independent generation (diversity ceiling). Hypothesis: profiles maintain diversity within expected bounds.
