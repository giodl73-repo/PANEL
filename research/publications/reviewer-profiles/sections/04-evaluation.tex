\section{Evaluation}

\subsection{Ablation Study: Isolating Mechanisms}

Across 25 test papers $\times$ 3 conditions $\times$ 2 rounds = 150 review sessions, we measured token usage to isolate caching benefit from profile design benefit:

\begin{table}[h]
\centering
\begin{tabular}{lccc}
\toprule
\textbf{Condition} & \textbf{Tokens/Paper} & \textbf{vs Fresh (\%)} & \textbf{vs Cached-DB (\%)} \\
\midrule
Fresh (A) & 35,200 ± 2,100 & — & — \\
Cached-DB (B) & 18,400 ± 1,800 & -47.7\% ± 3.2\% & — \\
Profiles (C) & 9,800 ± 1,200 & -72.2\% ± 2.8\% & -46.7\% ± 4.1\% \\
\bottomrule
\end{tabular}
\caption{Token usage by condition (mean ± 95\% CI). Caching provides ~48\% reduction; profiles provide additional ~47\% reduction beyond caching.}
\end{table}

\textbf{Key finding}: Profiles provide substantial benefit (47\%) even when compared to cached baseline, validating that profile architecture (not just caching) contributes to efficiency. Statistical significance: Fresh vs Cached-DB ($p < 0.001$, $d = 2.1$), Cached-DB vs Profiles ($p < 0.001$, $d = 1.8$).

\subsection{Token Reduction Analysis}

\subsubsection{Overall Reduction}

Fresh baseline vs. Profiles: 72.2\% ± 2.8\% reduction (95\% CI: [68.9\%, 75.5\%]). Per-paper savings: 25,400 ± 1,900 tokens. Effect size: Cohen's $d = 2.6$ (very large effect).

\subsubsection{Per-Venue Breakdown}

Token reduction varies by venue (F(9, 240) = 3.2, $p = 0.001$):

\begin{itemize}
\item \textbf{HCI venues} (CHI, CSCW): 74\% reduction (longer reviews, more context)
\item \textbf{ML venues} (NeurIPS, ICML, AAAI): 71\% reduction (technical depth)
\item \textbf{NLP venues} (ACL, EMNLP): 73\% reduction (domain-specific vocabulary)
\item \textbf{Systems} (PLDI, OSDI): 70\% reduction (implementation focus)
\item \textbf{Theory} (STOC, WWW): 69\% reduction (proof-oriented reviews)
\end{itemize}

Variance analysis reveals that review length (primary factor, η² = 0.42) and reviewer expertise specificity (secondary, η² = 0.18) explain most of the venue differences.

\subsubsection{P1 Item Overlap}

Automated analysis: 92\% of P1 items (high-impact issues) appear in both conditions. Manual verification of 50 discrepant cases: 38 are phrasing differences (same underlying issue), 12 are legitimate differences (6 in each direction, no bias detected).

\subsection{Consistency Improvement}

Cross-round correlation of reviewer positions:

\begin{itemize}
\item \textbf{Fresh baseline}: $r = 0.68$ ± 0.09 (moderate consistency)
\item \textbf{Profiles}: $r = 0.84$ ± 0.06 (high consistency)
\item \textbf{Improvement}: +23.5\% ± 4.2\% ($p < 0.001$, $d = 1.4$)
\end{itemize}

Longitudinal analysis (rounds 1-3): persona drift significantly lower in profile condition (slope: -0.02 vs -0.08 similarity decrease per round, $p = 0.003$). Profiles maintain stable persona across multiple review cycles.

\subsection{Diversity Maintenance}

Inter-reviewer perspective variation (entropy over issue categories):

\begin{itemize}
\item \textbf{Negative control} (identical profiles): $H = 1.2$ bits (diversity floor)
\item \textbf{Fresh baseline}: $H = 3.8$ ± 0.4 bits
\item \textbf{Profiles}: $H = 3.9$ ± 0.3 bits
\item \textbf{Positive control} (fully independent): $H = 4.2$ bits (diversity ceiling)
\end{itemize}

Profiles maintain diversity within expected bounds (no significant difference from baseline, $p = 0.31$). Vocabulary overlap (Jaccard similarity): baseline 0.32 ± 0.08, profiles 0.34 ± 0.07 ($p = 0.19$).

\subsection{Robustness \& Failure Modes}

\subsubsection{Persona Drift Analysis}

Plot semantic similarity to original profile over 5 rounds:

\begin{itemize}
\item \textbf{Fresh baseline}: Linear decay, $r_{round1 \rightarrow round5}$ drops from 0.85 to 0.62 (Δ = -0.23)
\item \textbf{Profiles}: Stable, $r$ drops from 0.87 to 0.80 (Δ = -0.07)
\item \textbf{Drift reduction}: 70\% lower degradation rate ($p < 0.001$)
\end{itemize}

\subsubsection{Hallucination Rate}

Factual consistency checking (cite-check against reviewer's actual publications):

\begin{itemize}
\item \textbf{Fresh baseline}: 3.2\% hallucination rate (invented publications, incorrect affiliations)
\item \textbf{Profiles}: 1.1\% hallucination rate (67\% reduction, $p = 0.004$)
\end{itemize}

Structured profiles with explicit publication lists reduce hallucination by grounding persona facts.

\subsubsection{Generic Fallback Detection}

Vocabulary overlap with generic reviews (no persona injection):

\begin{itemize}
\item \textbf{Fresh baseline}: 28\% overlap (moderate generic fallback)
\item \textbf{Profiles}: 18\% overlap (36\% less generic, $p < 0.001$)
\end{itemize}

Profiles maintain distinctive voice even under uncertainty, reducing generic fallback behavior.

\subsubsection{Failure Mode Frequency}

Across 150 review sessions (25 papers × 3 conditions × 2 rounds):

\begin{itemize}
\item \textbf{Persona drift} (similarity < 0.70): Fresh 12\%, Profiles 3\%
\item \textbf{Hallucination} (factual error): Fresh 3.2\%, Profiles 1.1\%
\item \textbf{Generic fallback} (vocabulary overlap > 35\%): Fresh 8\%, Profiles 2\%
\item \textbf{Overall failure rate}: Fresh 23.2\%, Profiles 6.1\% (74\% reduction)
\end{itemize}

\subsection{System Overhead}

\subsubsection{Profile Loading Latency}

Measured across 25 papers × 5 reviewers = 125 profile loads:

\begin{itemize}
\item \textbf{50th percentile}: 12ms (file I/O + YAML parsing)
\item \textbf{95th percentile}: 28ms (cache miss, cold start)
\item \textbf{99th percentile}: 45ms (outliers, disk contention)
\end{itemize}

Database loading: 50th = 87ms, 95th = 134ms, 99th = 201ms. \textbf{Profiles are 7.25× faster to load} (median comparison, $p < 0.001$).

\subsubsection{Memory Footprint}

\begin{itemize}
\item \textbf{Database approach}: 11.5KB cached in memory per session
\item \textbf{Profiles approach}: 5 profiles × 2KB = 10KB cached per session
\item \textbf{Difference}: Negligible (1.5KB savings, 13\% reduction)
\end{itemize}

Memory overhead is not a primary concern; token efficiency is the dominant benefit.

\subsubsection{End-to-End Request Latency}

Total review generation time (includes LLM API call, which dominates):

\begin{itemize}
\item \textbf{Fresh baseline}: 42.3s ± 8.2s per review
\item \textbf{Profiles}: 41.8s ± 7.9s per review
\item \textbf{Overhead}: -0.5s (not significant, $p = 0.74$)
\end{itemize}

Profile loading overhead (<50ms) is negligible compared to LLM inference time (~40s). Token reduction does not come at the cost of increased latency.
