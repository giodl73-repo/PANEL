# PITFALL Doctrine Integration

## Scope

Add PANEL's PITFALL doctrine index for recurring AI-simulated review failures,
then connect it to README discovery, role routing, plugin lifecycle evidence,
probe evidence, and portfolio reuse.

## Findings

- Simulated expert review can be mistaken for real peer review, external
  endorsement, factual certification, or venue acceptance evidence.
- Stage automation can skip evidence when `_panel.yaml` labels advance without
  the required reviews, synthesis, revision, module review, submission, or
  acceptance proof.
- Synthesis can become consensus theater if P1/P2/P3, PP1/PP2/PP3, B1/B2/B3,
  scores, or verdicts hide dissent, evidence, subject nuance, or author choice.
- Persona registries can drift into impersonation, duplication, noise, or
  venue-mismatch when more profiles are treated as more evidence.
- Probe evidence is currently an open risk: stored reports must be regenerated
  against the current plugin layout, skill count, command surface, and
  publication inventory before being cited as fresh proof.

## Integration

- `.pitfall/PITFALL.md` indexes PANEL principles, invariants, and pitfalls.
- `.pitfall/panel-principles.md` maps durable decision rules to README, CLAUDE,
  role, probe, plugin, and adopter-provenance evidence.
- `.pitfall/panel-invariants.md` records disclosure, stage-gate, re-entrancy,
  synthesis, and plugin-provenance properties.
- `.pitfall/panel-pitfalls.md` records mitigated and open failure classes for
  future plugin, research, and portfolio-adoption work.
